# RAG Index Rebuild Verification

- Date: 2026-09-10
- Change: refresh-published-cv (JOS-123)
- Agent: Claude Sonnet 5
- Trigger: `/verify` FAIL — the live chat widget answered "Who is Jose?"
  with the superseded title ("Technical Delivery Manager") despite
  `content/faq.md` and `content/profile.yaml` already stating the
  correct one ("Director of Delivery & Engineering") on disk.

## Root cause (two layers deep — first fix attempt was insufficient)

**Layer 1**: `public/rag-index.json` / `lib/rag/index.json` were dated
2026-09-06, before this change's content edits — stale relative to
`/content`. `npm run prebuild` regenerates both from current content.

**Layer 2 (the actual blocker, found after Layer 1's fix didn't work)**:
`next.config.ts`'s `initOpenNextCloudflareForDev()` gives `next dev` a
Cloudflare ASSETS binding; `lib/rag/retrieve.ts`'s `loadIndex()` fetches
the index through that binding, which serves from
**`.open-next/assets/rag-index.json`** — a *separate* build artifact
from `public/rag-index.json`, only regenerated by `npx
opennextjs-cloudflare build`. Confirmed: after running `npm run
prebuild` (Layer 1's fix), `.open-next/assets/rag-index.json` was still
dated **2026-08-31** and still contained the old title. A dev server
started before that file is regenerated also keeps serving the old
answer even after it's fixed on disk — the ASSETS binding is read once
per process start, not per request.

## Commands Executed

1. `npm run prebuild` — regenerated `lib/rag/index.json` /
   `public/rag-index.json` (91 chunks). **Insufficient alone.**
2. Started `next dev`, re-asked "Who is Jose?" via the live chat widget
   → still returned the old title. This is what surfaced Layer 2.
3. Inspected `.open-next/assets/rag-index.json` directly — confirmed

4. `npx opennextjs-cloudflare build` — reruns `prebuild`, then rebuilds
   `.open-next/assets/` from the fresh index.
5. Killed the dev server that predated step 4, started a new one.
6. Re-asked the identical question via the live chat widget.
