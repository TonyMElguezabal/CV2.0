## 5. Display gradient (AC: "restricted to large text and remains real text")

- [x] 5.1 Wrote `components/heroGradient.test.tsx` (7 tests). One iteration mid-TDD: my first draft put the gradient class directly on `heroNameClass`. Before implementing, reasoning through the CSS caught a real defect that draft would have shipped — `-webkit-text-fill-color` inherits to children in WebKit/Blink, so nesting the accent word inside a gradient-classed ancestor would silently make the accent word invisible too (the child's own `color` doesn't override an inherited `-webkit-text-fill-color`). Revised the test *before* writing implementation: gradient class must be its own constant (`heroDisplayGradientClass`) applied to a sibling span, never an ancestor of the accent span. One import bug in the test itself (three heading classes imported from the wrong file — `HeroShellStyles.ts` instead of their real section files) surfaced as `undefined` at runtime and was caught by `not.toContain` throwing on non-string input; fixed before the suite was trusted. All non-trivial assertions failed pre-implementation as expected.
- [x] 5.2 `heroDisplayGradientClass` in `HeroShellStyles.ts`: `bg-clip-text [-webkit-text-fill-color:transparent] bg-[linear-gradient(180deg,#ffffff_0%,#ece7dd_38%,#9a8f7e_82%,#6f6558_100%)]`. Deliberately **not** Tailwind's `text-transparent` (unconditional `color:transparent`, hides text in every browser with no fallback) — the fallback color is the inherited `text-ink` already on the outer `heroNameClass`, which is exactly what a browser without `bg-clip-text` support renders, since non-WebKit browsers simply ignore the vendor-prefixed `-webkit-text-fill-color` declaration.
- [x] 5.3 `HeroFramer.tsx` now splits `name` (a pure `splitHeroName` helper — last word, which for this site's actual "Jose Muñoz" is also literally the second word) into a lead `<span>` (gradient class) and an accent `<span>` (`heroAccentWordClass = "text-accent"`), rendered as **siblings** inside the `<m.h1>`, with an explicit `{" "}` text node between them so the accessible name doesn't collapse the words together. Single-word names fall back to gradient-only, no accent split. Runs at render time (pure function, not a client effect), so no-JS visitors get the same split in the server-rendered HTML.
- [x] 5.4 Verified: no `<img>`/`<svg>`/`<canvas>` inside the heading, and `heading.textContent` equals the exact input string — the gradient is confirmed to be a paint effect over real text, not a replacement.
