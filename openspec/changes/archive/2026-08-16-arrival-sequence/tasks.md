## 1. Fail-visible foundation — build this FIRST (AC: "bounded and never blocks reading or interaction")

Ordered before any choreography, for the same reason as JOS-111: an orchestrator
is a single point of failure for the entire page's visibility. Building the
sequence first and the safety net second is how a CV ends up blank.

- [x] 1.1 Added `components/ArrivalSequenceProvider.ssr.test.tsx` (2 tests: SSR bakes `opacity:0` into the raw HTML, which the shared `<noscript>` override exists to counteract; the override CSS itself forces full visibility) and `components/ArrivalSequenceProvider.test.tsx`'s "fail-visible: the orchestrator throws" describe block. **Real bug caught by this test, not simulated**: the first implementation wrapped deep-link detection in `try { … } finally { setState(...) }` — the `finally` block ran the state update, but did not stop the original exception from continuing to propagate out of the `useEffect`, which React then surfaced as an uncaught error rather than the page simply rendering visible. Fixed by using `try/catch` (which fully absorbs the exception) instead of `try/finally` (which only guarantees cleanup runs, not that the exception is swallowed) — confirmed via `git diff`, not by inspection alone
- [x] 1.2 Implemented `components/arrivalSequence.ts` (pure step-timing data + `detectDeepLinkSkip`), `components/ArrivalStyles.ts` (`arrivalAnimatedClass` marker + `arrivalNoscriptOverrideCss`, mirroring `RevealStyles.ts`'s established shape), and `components/ArrivalSequenceProvider.tsx` (`ArrivalSequenceProvider` + `useArrivalStep` hook). `arrived` starts `false` (matching SSR) and is flipped `true` by a mount effect — same starts-false-flips-once shape as `useRevealOnScroll`, but unconditionally on a mount tick rather than an `IntersectionObserver`, since an arrival sequence has nothing to observe. A consumer rendered outside the provider (context default) also resolves fully visible — one more fail-visible layer, matching the philosophy that "missing" is treated the same as "failed"
- [x] 1.3 Added `components/ArrivalSequenceProvider.test.tsx`'s "never blocks interaction" describe block (2 tests): a structural check that `useArrivalStep`'s returned style only ever contains `opacity`/`y` — never `pointer-events` or a disabled flag — across every branch (normal, no-offset, implicitly skip/reduced-motion via the shared return shape); and a functional test rendering a real `<button>` inside a step wrapper, confirming it is not disabled and fires its click handler immediately
- [x] 1.4 Verified: `ARRIVAL_STEP_DELAYS`'s own tests (`arrivalSequence.test.tsx`) confirm every delay is a fixed constant well under `pace.duration`, so the sequence's total bound is `max(delay) + pace.duration` — a compile-time-fixed value, not something that can grow unbounded. `ArrivalSequenceProvider.test.tsx`'s "reaches the visible animate target once the mount effect has run" confirms every participant lands in final state
