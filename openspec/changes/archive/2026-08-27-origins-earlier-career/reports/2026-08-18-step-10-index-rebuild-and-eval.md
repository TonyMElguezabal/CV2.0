## Root Cause: Stale `.open-next/assets` Index

The first `eval:chat` run showed **zero** origins chunks retrieved for any
of the five new origins questions — despite `npm run build` having just
regenerated a 91-chunk index. Traced to: `eval-run.ts`'s
`initCloudflareContextForScript()` gets its ASSETS binding from wrangler's
`getPlatformProxy()`, which serves files from `.open-next/assets/`, a build
artifact distinct from `public/rag-index.json` (the file `npm run build`'s
`prebuild` chain actually refreshes). `.open-next/assets/rag-index.json` is
only regenerated by `opennextjs-cloudflare build` (the first half of
`npm run preview`) — a step this change's task list, and apparently every
prior use of `eval:chat` in this repo, never ran. Confirmed via direct
inspection: `.open-next/assets/rag-index.json` was dated Aug 15, 86 chunks,
0 origins — three days stale.

Ran `npx opennextjs-cloudflare build` directly; confirmed
`.open-next/assets/rag-index.json` picked up all 91 chunks. This is a
process gap independent of this change's content — any future change that
runs `eval:chat` after a content edit needs this step too. Recorded in
Task Group 14 (technical documentation).
