## 1. Fail-visible foundation — build this FIRST (AC: "Revealed content is never left permanently hidden")

Deliberately ordered before any visual work. Building the reveal first and adding
the safety net after is how content ends up permanently hidden in an edge case
nobody exercised.

- [x] 1.1 Added `components/useRevealOnScroll.test.tsx` (7 tests: starts not-revealed out of view, reveals via observer, reveals via the scroll-listener fallback when the observer never fires, reveals immediately if already in view at mount, fails visible when `IntersectionObserver` is unsupported, is idempotent, cleans up its observer/listener) and `components/SectionReveal.ssr.test.tsx` (documents that SSR output genuinely renders `opacity:0` — the exact reason the shared `<noscript>` override exists — plus a content test on the override CSS string itself). **Honestly disclosed**: 3 of the hook's tests initially failed for a test-authoring reason, not a hook bug — manual `fireIntersecting`/`window.dispatchEvent` calls in the test bypassed React Testing Library's `act()` batching. Fixed by wrapping both in `act()`; the hook's own logic was correct from the first write
- [x] 1.2 Implemented: `useRevealOnScroll` (the hook) + `SectionReveal` (the consuming component) — `revealed` starts `false` and only a confirmed in-view check ever sets it `true`, never the reverse. Content's *default* rendered state is what fails visible, not a mechanism that must fire to become visible — matches design.md Decision 2's "readable unless something actively animates it in" framing exactly
- [x] 1.3 Added ONE shared `<noscript>` override in `app/(marketing)/layout.tsx` (not a per-instance duplicate like `HeroFramer.tsx`'s own, since this system will have many instances) — extracted as a reusable, directly-testable constant `revealNoscriptOverrideCss` in `RevealStyles.ts`. Also discovered and fixed a real prerequisite gap while wiring this up: `SectionReveal`'s `m.div` requires a `LazyMotion` boundary (framer-motion's `strict: true` mode throws without one), and `<main>` (where every content section lives) had no `MotionProvider` — `HeroFramer.tsx`/`HeroLaptop.tsx` only wrap their own subtrees. Added a `MotionProvider` around `{children}` in the layout rather than touching the hero components at all (nested `LazyMotion` providers are safe — same cached feature bundle)
- [x] 1.4 Covered by `useRevealOnScroll.test.tsx`'s own idempotency test: once revealed, a later scroll event with the element back out of view does not flip `revealed` back to `false` (the hook has no code path that ever does so — `revealed` only ever transitions `false → true`, once, by construction)

## 2. Heading reveal — cross-fade construction (AC: "Headings reveal with a blur-up treatment that animates only opacity and transform")

- [x] 2.1 Added `components/RevealHeading.test.tsx` (7 tests, Task Group 2 describe block): ghost carries a static blur class with `.style.filter` always empty; no span, before or after reveal, ever has an inline `filter` style; every animated span's only-ever-set inline style properties are limited to `opacity`/`transform`/`transform-origin` (framer-motion's own internal property, not something we set); per-character stagger structure (one sharp copy per character, in order); exactly one ghost + one sharp per character
- [x] 2.2 Built `components/RevealHeading.tsx` — per character, a statically-blurred (`RevealHeadingStyles.ts`'s `revealHeadingGhostBlurClass`, a plain Tailwind class, never in any `initial`/`animate` object) ghost copy cross-fading against a sharp copy. **Revised during Task Group 9 real-browser verification** (see design.md Decision 1's amendment): the original construction nested the ghost as a DOM sibling of the sharp copy inside one shared per-character wrapper; this was found to break native double-click/triple-click word-selection on the revealed heading. Fixed by moving all ghost characters into one separate, absolutely-positioned overlay span (`aria-hidden`, `pointer-events-none`) layered behind an uninterrupted run of sharp-copy character spans — proven experimentally in the live page to restore correct word-selection while leaving the cross-fade visually unchanged
- [x] 2.3 Ghost opacity `1→0`, sharp opacity `0→1`, both driven by the same `revealed` boolean, each carrying its own matching `translateY` rise (**revised**, per 2.2's note — no longer a single shared parent wrapper, since the ghost and sharp copies now live in separate DOM subtrees; both still receive the identical per-character `delay`, so they rise and cross-fade in lockstep)
- [x] 2.4 All three motion-controlled elements per character (wrapper, ghost, sharp) share one `transition={{ duration: pace.duration, ease: pace.ease, delay }}`, sourced from `components/motionPace.ts`
- [x] 2.5 `RevealHeading` is a general-purpose component (not scope-limited internally) — the **scope limit is enforced by usage**: it will only be wired into the three short section headings (Skills/Projects/Contact) in Task Group 4; chapter and project titles use `SectionReveal`'s whole-block treatment instead. - [x] 5.4 **New tests added** (the one real gap in this group — prior tests only checked the pre-reveal/initial state under reduced motion, never that the reveal actually completes): `SectionReveal.test.tsx`'s "under reduced motion, still reaches its fully visible final state once revealed" and `RevealHeading.test.tsx`'s "still reaches its fully visible final state once revealed under reduced motion" both fire a real intersection and `waitFor` the settled opacity to reach `1`, confirming reduced motion never leaves content stuck below full opacity. **Bug found and fixed while writing these**: `RevealHeading.test.tsx`'s pre-existing `revealNow()` helper never actually revealed anything — `useRevealOnScroll`'s `revealIfInView` re-checks `getBoundingClientRect()` itself rather than trusting the observer entry alone (its own fail-visible design), and this file's `beforeEach` leaves that mock at an out-of-view rect. Every earlier test using `revealNow()` happened to only assert structural things (filter empty, class presence) that hold true whether or not `revealed` ever flipped, so this was latent and undetected until a test needed the real settled value. Fixed by having `revealNow()` also swap in an in-view rect before firing, mirroring `SectionReveal.test.tsx`'s already-correct `fireIntersecting` helper — not a `RevealHeading`/`useRevealOnScroll` component bug, purely a test-helper gap
